RingKit requires **Capacitor 8** (iOS 14+, Android 8+). This page gets the plugin wired; the
platform pages cover the push setup that wakes a killed app: [iOS](/ringkit/ios),
[Android](/ringkit/android).

## 1. Install

RingKit is closed source: your license grants read access to the private repository, and you
install straight from it.

```bash
npm i github:Nickbur/ringkit#v1.0.0
npx cap sync
```

Every release is a git tag — pin the one you want. Installing in CI, pinning a copy without git,
and moving to a new version: [Installing and updating](#installing-and-updating).

<Note>
    No license yet? See [License](/ringkit/license) — $99/year per app.
</Note>

## 2. Configure

RingKit reads **static** config from `capacitor.config` under `plugins.RingKit` (it must be
static — on a killed app the JS layer isn't alive to configure the call):

```json
{
    "plugins": {
        "RingKit": {
            "appName": "Acme",
            "supportsVideo": true,
            "payloadPreset": "raw"
        }
    }
}
```

Every key is documented in [Configuration](/ringkit/configuration).

## 3. Platform setup

- **iOS** — add the **Push Notifications** capability and **Background Modes** → **Voice over
    IP** (and **Audio** for the call media), declare the microphone usage string, and send VoIP
    pushes to the token from the `registration` event with a **VoIP Services** APNs key or
    certificate (topic = your bundle id + `.voip`). RingKit reports the call from its PushKit
    delegate automatically. Full detail: [iOS setup](/ringkit/ios).
- **Android** — RingKit's permissions and components merge in automatically. Request the runtime
    **notifications** permission (Android 13+) before calls arrive, and deliver a
    **high-priority FCM data message** (at minimum `callId`) to wake the app: either declare
    RingKit's opt-in `RingKitMessagingService` (if you don't already have an FCM service), or call
    `RingKitIncomingCall.present(...)` from your existing handler (OneSignal, your own FCM, SIP).
    Full detail: [Android setup](/ringkit/android). Huawei without Google services:
    [HMS Push](/ringkit/hms).

## 4. Wire the call lifecycle

<Warning>
    Attach listeners **before** `register()`. The iOS VoIP token and an Android cold-start
    answer can fire the moment `register()` runs.
</Warning>

```ts
import { RingKit } from '@nickbur/ringkit';

async function setupCalls() {
    if (!(await RingKit.isAvailable()).available) return; // web/desktop → in-app ringing

    await RingKit.addListener('registration', ({ token, platform, apsEnvironment }) => {
        // Register `token` with your push provider so it can wake this device.
        // iOS: `apsEnvironment` ('development' | 'production') tells you which APNs
        // gateway / OneSignal test_type to route the VoIP token through.
    });

    await RingKit.addListener('callAnswered', async ({ callId, chatId, hasVideo }) => {
        await joinYourCall(callId, chatId, hasVideo);   // your media/SFU join
        await RingKit.reportCallConnected({ callId });
    });

    await RingKit.addListener('callEnded', ({ callId }) => {
        teardownYourCall(callId);
    });

    await RingKit.register();
}
```

## 5. Present a call

From a foreground/background push handler, present the native screen yourself. From a **killed**
app RingKit presents it for you (iOS PushKit delegate / Android FCM service — see the platform
pages).

```ts
await RingKit.reportIncomingCall({ callId, handle: 'Ada Lovelace', hasVideo: false, chatId });

// End it (remote hang-up / cancel):
await RingKit.endCall({ callId });
```

If the caller hangs up before the callee answers, a cancel push dismisses the ring even on a
killed device — see [Remote cancel](/ringkit/configuration#remote-cancel).

## 6. Try it without a push server

Clone the plugin's `example/` app and tap **Simulate incoming call** — it exercises
`reportIncomingCall` → native UI → `callAnswered`/`callEnded` on both platforms with no push
infrastructure. For the killed-app path, use the ready-made test-push senders in
`example/scripts/` — see [Testing](/ringkit/testing).

<Note>
    Gating your media start on the audio session is what prevents the iOS dead-microphone bug —
    see [In-call audio](/ringkit/audio).
</Note>

## How the killed-app path works

- **iOS** — RingKit registers its own `PKPushRegistry` for VoIP pushes. iOS wakes the app for a
    VoIP push and RingKit reports the call to CallKit synchronously (required by iOS), so the
    native screen appears even when the app was terminated.
- **Android** — a high-priority FCM data message starts RingKit's service in the background; it
    presents the call via Telecom or the full-screen fallback. When the user answers, RingKit
    revives your app (launcher intent) and flushes the `callAnswered` event on `register()`
    (cold-start actions older than `androidPendingActionTtlMs` are dropped).

## Installing and updating

### Access from your machine and from CI

npm fetches RingKit with git, so whatever runs `npm i` needs read access to the private
repository:

- **Your machine** — the GitHub account your license gives access to, signed in to git (an SSH
    key or a git credential helper). A "repository not found" or permission error from `npm i`
    means git couldn't authenticate.
- **CI** — give the job a read-only credential for the repository (a deploy key, or a
    fine-grained token limited to reading its contents) and let git use it. Or skip git in CI
    entirely with a pinned tarball (below).

### Pinning a copy without git

Every release on the repository's **Releases** page has the packed package attached
(`nickbur-ringkit-<version>.tgz`). Download it into your project — for example a `vendor/`
folder you commit — and install from the file:

```bash
npm i ./vendor/nickbur-ringkit-1.0.0.tgz
npx cap sync
```

The build then needs no access to the repository, which keeps CI simple.

### Moving to a new version

<Steps>
    <Step title="Read the release notes">
        Each release on GitHub lists what changed; the repository's `CHANGELOG.md` has the full
        history.
    </Step>
    <Step title="Install the new tag (or tarball)">
        ```bash
        npm i github:Nickbur/ringkit#v<new-version>
        npx cap sync
        ```
    </Step>
    <Step title="Rebuild the native apps">
        Rebuild and test the iOS and Android apps — RingKit's native code changes with the
        plugin. The killed-app path is worth re-checking with the [test senders](/ringkit/testing).
    </Step>
</Steps>

Only the latest release receives fixes, so stay on it. New versions are yours while the
subscription runs; if it lapses, you keep shipping the versions you already built.
