RingKit is **closed source**. The repository is private; a current subscription is what
grants read access to it, alongside the right to ship the plugin in your app.

<Card title="Buy a license — $99/year per app" href="https://ringkit.dev" icon="key">
    After checkout you are given read access to the private repository and install straight
    from it.
</Card>

## In short

| | |
| --- | --- |
| **Price** | $99 / year, per application |
| **What an "application" is** | One distinct end-user app, identified by its store listing and bundle id / application id family. Build flavours and platform variants of the same product count as one. |
| **What you may do** | Ship the plugin, in compiled form, inside that one application — in production, commercially, to any number of end users. Read, debug and modify the source internally for that purpose. |
| **What you may not do** | Redistribute the source, share repository access, mirror the repository, publish excerpts, or ship RingKit as a library/SDK of your own. |
| **Client work** | Allowed — one subscription per delivered application. The agency or the client may hold it. |
| **If the subscription lapses** | You may keep shipping the versions you built while it was active. You lose repository access, updates and support until you renew. |
| **Support** | The private repository's issue tracker, best-effort, no SLA. |

The source is closed, so this documentation is the thing to judge RingKit by: the
[API reference](/ringkit/api), the per-platform setup for [iOS](/ringkit/ios) and
[Android](/ringkit/android), the [reliability deep-dive](/ringkit/reliability), the

plainly when a free plugin is the better buy. If something you need to decide on is missing
from it, ask at [support@burakov.net](mailto:support@burakov.net) — it gets answered, and usually documented.
