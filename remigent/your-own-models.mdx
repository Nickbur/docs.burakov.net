Remigent runs **only on open-weight models**. It doesn't resell tokens: you bring your own access to the models, and
every call is billed to you at your provider's prices — or runs on hardware you already own.

## Why open weights

- **Selected and tested.** Remigent selects the models it runs on and tests them on real tasks, so its quality and
  its cost forecasts stay predictable.
- **Can't be taken back.** A closed model can be repriced, changed or retired overnight. Open weights stay available,
  so the model your work was tested on stays the same model.
- **Yours to run.** The same models run through a hosted provider or on your own hardware — nothing locks you to a
  single lab or a single vendor.

## How the models are chosen

Remigent chooses the models — there is nothing to choose or tune. It picks open-weight models as close as possible to
the best proprietary ones, and changes them only when a newer one passes the same checks on real tasks.

## Connect the models

| Route | What you bring | Notes |
|---|---|---|
| **OpenRouter** | one OpenRouter API key | every model Remigent uses through one key, billed by OpenRouter at its prices |
| **Your own hardware** | an OpenAI-compatible server — vLLM, SGLang, Ollama or your own — serving the models the dashboard lists | no token bill; the hardware is yours |

You can connect both: work runs on your server where it can, and through OpenRouter otherwise.
When you add your own server in **Connections → Models**, the dashboard shows the models it needs to serve. Serve them
at their original precision or higher — a reduced-precision copy is a different model from the one Remigent tested.

Through OpenRouter, Remigent sends each call only to hosts it has checked serve the model at full quality; you don't
pick or manage hosts.

<Note>
    A server on your own network (for example `localhost`) is reachable only from a
    [self-hosted runner](/remigent/self-hosted-runner). With hosted compute, your server must be reachable from the
    internet, with its URL and key.
</Note>

## Your keys stay protected

- **Hosted compute:** your keys are stored encrypted with a key unique to your workspace, decrypted only
  in memory for the job that needs them, and never logged.
- **Self-hosted runner:** your keys live only in the runner's configuration on your machine — Remigent
  never receives them.
- **Model keys never enter the sandbox** where code runs, so code under test can't read them.

## When a model is unavailable

If a model Remigent uses goes down, work doesn't stop: it continues on a **tested backup model** that passed the same
checks on real tasks. Remigent keeps checking the usual model and switches back on its own as soon as it returns.
While a backup is in use, the dashboard says so; a pull request made partly on it says so too. Verification and the
judge's verdicts are the same either way.

## Your code is never used for training

Remigent never uses your code or data to train models. Fleet memory stays inside your workspace; sharing
anonymous, non-proprietary patterns across customers is strictly opt-in.

By default, calls through OpenRouter go only to hosts that keep no copy of your requests. The workspace Owner can
widen the choice to hosts that may keep or learn from them, in **Settings**.
