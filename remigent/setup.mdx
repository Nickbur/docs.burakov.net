description: "Set up Remigent as a workspace owner — connect git, model keys and compute, add projects, take the onboarding interview, and set the budget."

---

Setting up takes two kinds of work: **forms** for the mechanics (connections, keys, budget) and an **interview** for
judgment (your vision, taste and priorities). Autonomy stays off until both are done. You can stop at any point and
resume later — the dashboard shows how far you've got.

## 1. Sign in

Open [app.remigent.com](https://app.remigent.com) and sign in with your email and a one-time code. Your workspace is
created with you as its **Owner** — the account that holds the plan and pays for it.

## 2. Connect your git host

In **Connections → Repositories**:

| Host | How it connects |
| --- | --- |
| **GitHub**, **GitLab.com** | Install the Remigent app on your account or organization and pick the repositories. It gets narrow, revocable permissions — enough to push branches and open pull requests. |
| **Self-hosted GitLab, Gitea, any other server** | A service-account token for pull requests, plus a deploy key for git over SSH. |

Remigent never asks for a broad personal access token. With a [self-hosted runner](/remigent/self-hosted-runner), the
token and deploy key for any host other than the GitHub app stay in the runner's own configuration instead. Your
**14-day Studio trial** starts when you connect your first git account — see [Pricing](/remigent/pricing).

## 3. Choose where code runs

Your code always runs on **your** compute. The **Owner** picks the mode in **Settings → Where the work runs**:

- **Managed** — in **Connections → Compute**, add your **E2B**, **Daytona** or **Modal** API key;
- **Self-hosted** — in **Connections → Compute**, enroll a **self-hosted runner**.

See [Compute & sandboxes](/remigent/compute).

## 4. Connect the models

Remigent runs only on open-weight models. Bring your OpenRouter key, an OpenAI-compatible server on your own hardware
that serves the models the dashboard lists, or both. Where they go depends on the mode:

- **Managed** — add it in **Connections → Models**; it's kept encrypted in Remigent's vault;
- **Self-hosted** — put it in the runner's configuration (`REMIGENT_PROVIDERS`); it never reaches Remigent. See
    [Self-hosted runner](/remigent/self-hosted-runner#models).

Remigent selects the models itself — there is nothing to choose. When you add your own server, the dashboard shows the
models it needs to serve; if it doesn't serve all of them, connect OpenRouter too. See [Open-weight models](/remigent/your-own-models).

## 5. Add projects

A **project** is one product, made of one or more repositories. In **Projects**, choose **Add project** and pick its
repositories.
When one repository holds several products, give each project the paths it owns; paths no project claims are treated
as your **shared platform**. See [Projects & your fleet](/remigent/projects-and-fleet).

## 6. Take the onboarding interview

Remigent studies each repository first — its code, dependencies, tests and docs — then interviews you, one question at
a time, each with a recommended answer you can accept or change:

- your **product vision**, invariants, taste and priorities — this becomes the **constitution**;
- how you commit and name branches;
- each repository's **verification recipe** — how to build, test and run it (see
    [Verification recipe](/remigent/recipe));
- which **expert profiles** may work on what (for example "anything touching auth also gets a security review").

For a new product, the interview helps you shape the vision first. Nothing enters the constitution until you confirm
it.

## 7. Set budgets and preferences

| Setting | Where | Default |
| --- | --- | --- |
| **Monthly spending cap** | **Budget** | — (required) |
| **Compute cap** *(managed sandbox providers)* | **Budget** | off |
| **Daily attention budget** | **Settings** | 30 min a day |
| **Commit authorship** | **Settings** | `remigent[bot]` |
| **Language of plans and pull requests** — for the constitution, pull requests and commits | **Settings** | English |
| **Observation after merge** | **Settings** | 72 hours |
| **Notifications** — your own channels | the **Notifications** page (the bell); workspace defaults in **Settings** | in-app and email |

## 8. Autonomy switches on

Once the constitution is confirmed and the budget is set, Remigent starts working. Its first pull request in each
repository adds a `.remigent/` directory — the constitution's read-only copy and the recipe — for you to review and
merge like any other change.
