Channels feed the same [inbox](/remigent/feeding-work) as the dashboard. An **Owner or Admin** connects them in
**Connections → Channels**; each one is mapped to the project it belongs to (a Sentry project, a store app, a
repository).

## Available channels

| Category | Channel | How it connects | Trust |
| --- | --- | --- | --- |
| **Your team** | Dashboard inbox — text, screenshots, files | Built in | trusted |
| | **Email-in** | A Remigent address per workspace or per project — send or forward to it | trusted from members |
| | **Telegram bot** | Link the bot to your account; it also delivers notifications | trusted |
| | **GitHub / GitLab issues** labelled `remigent` | Through your repository connection | trusted from members |
| **Errors & crashes** | **Sentry** — cloud or self-hosted | An auth token and the projects to watch | outside input |
| **Store reviews** | **Google Play**, **App Store Connect** | API credentials and the app to watch | outside input |
| **Support** | Any help desk | Forward to the email-in address, or send a generic webhook | outside input |
| **Product metrics** | **PostHog** | A project API key | data |
| **Uptime** | Uptime Kuma, Better Stack and others | A generic webhook | data |
| **Community** | GitHub issues and discussions from people outside your workspace | Through your repository connection | outside input |
| **Anything else** | Generic webhook | A per-project webhook URL | outside input |

Channel credentials are stored in your workspace's encrypted vault.

## Trust

Remigent treats input by where it comes from:

- **Your team** — trusted, within each person's [role](/remigent/team-and-permissions).
- **Outside input** — reviews, support messages, crash reports, issues from strangers. It's first read in isolation,
    with **no tools, no code and no secrets**, and turned into a structured item; raw outside text never reaches
    the work that writes code. Outside input can start only **maintenance work** — a bug, a security issue, a
    performance problem. A feature request from the public becomes a **proposal** for you.
- **Data** — metrics and uptime signals, used to measure the effect of merged changes.

Duplicates are merged, and Remigent's sense of what is worth doing plus your budget cap keep a flood of reviews from
turning into a flood of spending. Only the excerpt Remigent needs is stored, for up to **180 days**.

## After a merge

Errors, reviews, support, metrics and uptime are also what Remigent watches **after you merge**: if a change makes
them worse within the observation window (72 hours by default), it opens an urgent revert pull request. With no
channels connected, pull requests say plainly that nothing was observed. See [Verification](/remigent/verification).
