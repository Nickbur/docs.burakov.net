The operator admin panel — a Vue 3 SPA on its own origin, run against `shipwide_api`. It reads
every account's data and every support thread, so serve it **separately** from the app and put
it behind a network gate (Cloudflare Access, IP allowlist). Single-app: no product registry or
multi-app machinery — the surface is what a single-app operator needs (accounts, sessions,
support tickets, uploads, push, audit, ops).

## Screens

Twelve screens, all in the side navigation or one click from it:

| Screen | What you do there |
|--------|-------------------|
| **Dashboard** | What the system is doing right now: open tickets, active accounts, new sign-ups today, live sessions, uploads, accounts awaiting purge. |
| **Accounts** | Search and filter everyone with an account — active or deleted, user or admin. |
| **Account detail** | One account: profile, second factor, sessions, subscription and entitlements, username history. Make or remove an admin, mark a test/review account, sign it out everywhere, delete, restore or purge it, and [grant a free period](/shipwide/billing#granting-a-free-period). |
| **Support** | The ticket inbox — filter by status and topic, search by subject. See [Support & tickets](/shipwide/support). |
| **Ticket** | One thread: reply (the user gets it by email and push), change the status, or delete the ticket. |
| **Sessions** | Every live session across the app, the website and this panel; revoke any of them. |
| **Uploads** | Files users uploaded — moderate content and clear out failed or stuck uploads. |
| **Push** | Send a notification to one account or broadcast it to every subscribed device. |
| **Audit** | Every change made through the panel, with who made it and what it changed. |
| **Ops** | API health and the configuration it runs with; run the retention purge by hand. |
| **Settings** | The app version policy (latest and minimum supported version) — see "App version policy & upgrade gate" in [Backend](/shipwide/backend). |
| **Your account** | Set up or turn off the second factor (TOTP) for your own sign-in and get new recovery codes. |

## Design & i18n

- **Design system is the Shipwide site's** — same tokens/buttons/badges/`<dialog>`/header/footer,
    plus an `Admin` mark beside the brand so it's never mistaken for the public site.
- **Multilingual (en + ru to start).** Language + theme switch from the header and sign-in
    screen, both remembered; dates and relative times follow the chosen language.
- **The language picker scales** to dozens of languages — endonyms, a filter box once there are
    more than eight, and a list that scrolls.
- **Add a language** by dropping `<code>.json` into `src/i18n/locales/` + one line in
    `src/i18n/locales.ts` (`rtl: true` for RTL). The i18n machinery carries no product text, so a
    new language is just JSON.
- **Bundles load on demand** — only English (the fallback) is in the main chunk; every other
    language loads as a separate chunk (`import.meta.glob` + `setLocaleMessage`).
- **RTL wired** — a `rtl` flag drives `dir`; CSS uses flexbox + logical flow.

## Quick start

```bash
npm install
npm run switch_to_dev        # env/env.dev → .env (points at localhost:3001)
npm run serve                # http://localhost:5176
```

Vite inlines `VITE_*` at build time → switch to prod **before** building. The API must allow
this origin: `ADMIN_URL` in the API env is added to CORS, so `ADMIN_URL` and the port here must
agree.

**Scripts:** `switch_to_dev|prod` · `serve` (Vite :5176, `strictPort`) · `fix` (Prettier +
`eslint --fix`) · `build` (the quality gate: Prettier check + ESLint + `vue-tsc` + tests → `dist/`) ·
`setup-https` ([HTTPS in dev](/shipwide/https-dev)) · `license-check` (production-dependency
licences) · `re-install-deps` (clean reinstall).

**Tests:** `*.test.ts` next to the code — unit tests for the API client, token refresh, encrypted
storage, i18n and stores, and component tests that mount every screen with the network mocked
(Vitest + `@vue/test-utils` in happy-dom; shared helpers in `src/test/`). `build` measures coverage
and fails below 80% overall, 90% for `config`, `core`, `i18n`, `modules`, `router` and `stores`, or 80%
for any single file.
One file on its own: `npx vitest run <file> --coverage.enabled=false`.

## Signing in

The sign-in screen offers only what `GET /v1/admin/auth/methods` reports:

1. **Root credentials** — `ADMIN_LOGIN` + `ADMIN_PASSWORD` (API env). Independent of mail —
    works when everything else is broken. The password can be plaintext or a `scrypt$…` hash
    (`npm run admin:password -- 'pw'` in the API prints one). Per-login lockout plus a per-IP
    rate limit; leave both vars empty to switch this route off.
2. **Emailed one-time code** — staff-only passwordless route at `/v1/admin/auth/code`. The first
    admin comes from `ADMIN_EMAILS`: a listed address is made admin (or created) when it signs in.

If TOTP is enrolled, neither route returns a session directly — both hand back a 5-minute
challenge; a recovery code works in the same box.

### Security model (API side)

- **Short-lived sessions** — both routes land on an admin session (`client_id: admin`): 15-minute
    access and 12-hour refresh by default (`ADMIN_ACCESS_LIFETIME_MINUTES` /
    `ADMIN_REFRESH_LIFETIME_HOURS` in the API env).
- **TOTP is offered, never forced** — standard RFC 6238 codes, implemented on `node:crypto`. Once
    enrolled on an account (on **Your account**), every sign-in demands it. The secret is encrypted
    at rest (AES-256-GCM under `DATA_ENCRYPTION_KEY`) and bound to its own account row, so it can't
    be moved to another one. Recovery codes are stored hashed, so they still work if that key is
    ever lost — a TOTP check without the key answers `503 mfa_key_unavailable`.
- **Roles** are `user` and `admin`. `requireRole` reads the role fresh from the database on every
    request, so a demotion takes effect on the next call.
- **Every change is audited** — each mutating admin action is written to the `admin_audit` table,
    shown on the **Audit** screen. Reads aren't recorded.

## Architecture

```
src/
├── config/          # everything product-specific, driven by VITE_*
├── i18n/            # vue-i18n setup + en/ru locale files
├── core/            # the reusable half — assumes nothing about the product
│   ├── api/         # axios client, error classification, wire types
│   ├── auth/        # token pair, expiry maths
│   ├── storage/     # AES-GCM over IndexedDB
│   ├── ui/          # formatting
│   └── composables/ # confirm dialog
├── modules/         # every API call, in one file
├── stores/          # auth + chrome (Pinia)
├── components/      # header, footer, dialog, toasts, table pieces
├── views/           # one per screen
└── styles/          # the design system, ported from the site
```

<Note>
    **`core/` never names the product** — it keeps the reusable half free of assumptions about which
    API it administers or what the product is called, so you rebrand by editing `.env`, not code.
    Anything that would be a hardcoded string lives in `src/config/`.
</Note>

### Pieces that are easy to get wrong

- **One axios instance, not a factory.** Refresh is single-flight — every caller awaits the same
    promise, so two concurrent 401s don't each spend a rotating token.
- **Refresh happens before expiry**, not only on a 401 — admin sessions are short and the panel
    sits open between bursts.
- **Tokens in an encrypted IndexedDB store** (non-exportable `CryptoKey` + canary), loaded into
    memory before the app mounts. Keeps credentials out of plaintext at rest; not an XSS defence.
- **The router gate is not a security boundary** — the API authorises every request and re-reads
    the role each time. The gate only stops a dashboard that will never load.
- **Every `VITE_*` is declared in `src/vite-env.d.ts`** — a typo arrives as `undefined`, not a
    type error.
- **TypeScript pinned to 6.x, not 7.x** — TS 7 drops the JS `tsc` that `vue-tsc` 3 patches, so
    `build` throws under TS 7.
- **i18n in composition mode** — `errors.*` keys mirror the API's error codes; `en`/`ru` are kept
    at exact key parity.

## Environment

| Variable | Default | Notes |
|----------|---------|-------|
| `VITE_API_URL` | `http://localhost:3001` | The API this panel administers |
| `VITE_CLIENT_ID` | `admin` | Storage namespace / session label |
| `VITE_BRAND` | `Shipwide` | Header and footer — set to your product name |
| `VITE_SITE_URL` | — | Linked from the footer; empty hides the link |
| `VITE_DOCS_URL` | — | Your documentation, linked from the footer; empty hides the link |

Vite inlines these at build time → a change means a rebuild (and for Docker, the right
`--build-arg`).

## Deployment

```bash
docker build \
    --build-arg VITE_API_URL=https://api.example.com \
    --build-arg VITE_SITE_URL=https://example.com \
    --build-arg VITE_BRAND="Your product" -t shipwide-admin .
docker run -p 8080:80 shipwide-admin
```

nginx serves the SPA, falls through to `index.html`, caches hashed assets forever / `index.html`
never, sends `noindex` + `DENY`. Outside the image: (1) point `ADMIN_URL` in the API env at this
origin or CORS refuses it; (2) put a **network gate** in front — nothing here needs to be
publicly reachable.
