## Prerequisites

- **Node 24.16+** and npm (every part refuses to install on an older Node).
- **Docker** (for local PostgreSQL + Redis) — or your own Postgres 17 / Redis 7.
- Native builds only: **Xcode 26+** (iOS), **Android SDK 36 + JDK 21** (Android), **Rust
    stable** (desktop). Not needed to run the web app.

## 1. Backend (`shipwide_api`) — start here

<Steps>
    <Step title="Install and configure">
        ```bash
        cd shipwide_api
        npm install
        npm run switch_to_dev          # env/env.dev → .env (local defaults, ready as-is)
        ```
    </Step>
    <Step title="Start Postgres + Redis">
        ```bash
        docker compose up -d db redis  # Postgres :5433 + Redis :6380 (or: docker compose up --build for everything)
        ```
    </Step>
    <Step title="Migrate, seed, serve">
        ```bash
        npm run db:migrate
        npm run seed                   # test/review accounts (no-op if TEST_ACCOUNTS is empty)
        npm run serve                  # http://localhost:3001
        ```
    </Step>
</Steps>

Check it: `curl http://localhost:3001/v1/health`. Interactive API reference:
`http://localhost:3001/docs`. The minimum env is `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`
(≥32 chars) — `env.dev` sets them.

<Note>
    **Email in dev:** `EMAIL_DEV_MODE=true` prints one-time sign-in codes to the API console
    instead of emailing them, so the passwordless flow works with no SMTP.
</Note>

## 2. App (`shipwide_app`)

```bash
cd shipwide_app
npm install
npm run switch_to_dev              # env/env.dev → .env (points at :3001)
npm run serve                      # Ionic dev server (web) — http://localhost:8100
```

Sign in: enter any email → read the 6-digit code from the **API console** → you're in (an
unknown address is created on the spot). Native: `npm run build` (it ends with `cap sync`), then
open the `ios/` / `android/` project — see [App](/shipwide/app).

## 3. Admin panel (`shipwide_admin`)

```bash
cd shipwide_admin
npm install
npm run switch_to_dev              # env/env.dev → .env (points at :3001)
npm run serve                      # http://localhost:5176
```

Sign in with the `ADMIN_LOGIN` / `ADMIN_PASSWORD` you set in the **API's** env, or an emailed
staff code (printed to the API console). The first admin is bootstrapped from `ADMIN_EMAILS`.
The API allows this origin automatically via `ADMIN_URL` — keep `ADMIN_URL` and the port in
agreement.

## 4. Website (`shipwide_website`)

```bash
cd shipwide_website
npm install
npm run switch_to_dev              # env/env.dev → .env
npm run serve                      # http://localhost:4334
```

It's all placeholder content — see [Website](/shipwide/website) and
[Customization](/shipwide/customization) to make it yours.

## Ports

Each part has its own fixed port — API `3001`, app `8100`, admin `5176`, website `4334`, Postgres
`5433`, Redis `6380` — so the kit runs next to whatever else you have locally. The admin and the
website use `strictPort`: a taken port stops them with an error. The app's `ionic serve` instead
moves to the next free port, so if it comes up elsewhere, something is already on 8100. To change
a port, edit the part's `vite.config.ts` / `astro.config.mjs` (for the app also the `--port` in its
`serve` script; for the API `PORT` in its env) together with the env values that point at it
(`VITE_BACKEND_URL`, `VITE_API_URL`, `CORS_ORIGINS`, `ADMIN_URL`).

## Code quality (all four parts)

`npm install` also activates the git hooks (husky):

- **pre-commit** — a guard rejects accidental files (stray names from a mistyped shell command, new
    empty files without an extension, files over 2 MB unless listed in `.husky/large-files.txt`,
    unresolved conflict markers), then `eslint --fix` and Prettier run on the staged files.
- **commit-msg** — headers follow Conventional Commits: `type(scope): subject` (`feat`, `fix`,
    `chore`, `docs`, `refactor`, `test`, …).

In every part, `npm run build` is the quality gate: it starts with `prettier --check .` and
`eslint .`, then type-checks, runs the tests (app, admin panel, API and website — each with a coverage
gate: 80% overall, 90% for the logic folders) and builds. `npm run fix` applies
the automatic fixes (Prettier, then `eslint --fix`) — run it after writing code, review the diff,
then build. ESLint
is type-aware (typescript-eslint): a promise you deliberately don't wait for is written
`void doSomething()`. VS Code picks up the shared `.vscode/` settings (format and ESLint fixes on
save).
