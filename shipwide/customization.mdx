The kit ships as placeholder content over a shared design system (dusty-indigo accent, warm
neutrals, **Golos Text** display font). Here's how to make each part yours.

## Website — the fastest wins

<Steps>
    <Step title="Brand & product">
        `src/data/site.ts` — brand `name` (drives header/footer/titles everywhere), emails, socials,
        nav. `src/data/product.ts` — download links, pricing plans, features, screenshots.
    </Step>
    <Step title="Assets & domain">
        Replace the icon set in `public/` (`favicon.ico`, `favicon-16/32/48.png`,
        `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `icon-512-maskable.png`) and the
        social card `public/og-default.png`, and put your name in `public/site.webmanifest`; set
        `PUBLIC_SITE_URL` in `env/env.prod`.
    </Step>
    <Step title="Copy & screenshots">
        Swap the copy in `public/locales/en/*.json` (words live here; facts live in `src/data/`);
        drop your store screenshots into `src/screenshots/` named `01-…`, `02-…` (they render as a
        fan of phone mockups); delete the demo images.
    </Step>
</Steps>

Full detail: [Website](/shipwide/website).

## Design tokens & fonts (site + admin share the system)

- Tokens are CSS custom properties in `src/styles/_variables.scss` (light + dark themes).
- **Accent**: a dusty-indigo ramp `--accent-50…900`. Change `--accent-400` (dark) /
    `--accent-600` (light) and it propagates everywhere.
- **Neutrals** are warm greys, not pure zinc.
- **Display font**: Golos Text on headings (`--font-display`); system stack for body
    (`--font-sans`). Any OFL font (with Cyrillic if you keep RU) works. To swap it:
    - **Site** — it self-hosts the woff2 files from `public/fonts/` via the `@font-face` blocks in
        `src/styles/base/_fonts.scss`: replace the files, update those blocks, point
        `--font-display` at the new family, and update the preloaded file (`preloadFont`) in
        `src/layouts/Base.astro`.
    - **Admin** — it imports `@fontsource/golos-text` (weights 600 + 700) in `src/main.ts`:
        `npm install @fontsource/<name>`, change the two imports, point `--font-display` at it.

## App

- **`VITE_APP_NAME`** — your product's local namespace (storage, settings, cache, deep-link
    scheme). Set it **before** launch; changing it later orphans existing local data.
- **`VITE_CLIENT_ID`** — your app's id on every sign-in (the kit ships `shipwide`). If you change
    it, put the same value in the API's `CLIENT_IDS`, or sign-in fails with `unknown_client`.
- **App identity**: the kit ships named "Shipwide" with the id `com.example.shipwide`. Put your
    own name and id in each place before your first release (store ids can't change once
    published):
    - Web/PWA: the `manifest` in `vite.config.ts` (`name`, `short_name`, `description`,
        `theme_color`, `background_color`) and the `<title>` in `index.html`.
    - Capacitor: `appId` and `appName` in `capacitor.config.ts`.
    - Android: `applicationId` in `android/app/build.gradle` and the names in
        `android/app/src/main/res/values/strings.xml`.
    - iOS: the bundle identifier (Xcode → target → Signing & Capabilities) and
        `CFBundleDisplayName` in `ios/App/App/Info.plist`.
    - Desktop: `productName`, `identifier` and the window `title` in `src-tauri/tauri.conf.json`.
- **Icons**: desktop `src-tauri/icons/` is generated from `public/pwa-512.png` via
    `npx tauri icon`; regenerate the mobile icons and splash screens from your own source images in
    `assets/` (`icon.png`, `splash.png`, `splash-dark.png`); replace the PWA/app icons in `public/`.
- **Links**: `VITE_STORE_*_URL` (About "Update" button, per platform), `VITE_LEGAL_PRIVACY_URL`
    / `VITE_LEGAL_TERMS_URL`, `VITE_DOCS_URL` (your user guide), `VITE_DEVELOPER_URL` (About
    "Developed by …").
- **Screens**: the account / sessions / settings screens are stubs — build your product screens
    on the composables and api layer the kit provides.
- **Theme/design tokens** live in `src/styles/_variables/` (`colors.scss`, `custom.scss`,
    `fonts.scss`, `theme.scss`) — the same accent/neutral language as the site.
- **Dark theme overrides**: Ionic's own dark palette sets the surface colours
    (`--ion-background-color`, `--ion-text-color`, `--ion-toolbar-background`,
    `--ion-item-background`, `--ion-card-background`, …) on `.ion-palette-dark.md` /
    `.ion-palette-dark.ios` — two classes on `<html>`. Put your dark values for those under
    `.ion-palette-dark body, .ion-palette-dark` (as `styles/_variables/theme.scss` does), or
    Ionic's win.

## Admin

- `VITE_BRAND` (header/footer name), `VITE_SITE_URL` and `VITE_DOCS_URL` (footer links). `core/` never names the
    product — you rebrand by editing `.env`, not code.
- Shares the site's design tokens; recolour via the same accent ramp.

## Languages

- **Website**: 5-step add (see [Website](/shipwide/website) → Languages). Ships en + ru.
- **App**: copy `src/i18n/locales/en/` to `src/i18n/locales/<code>/` and translate the JSON files,
    then add the language to `LANGUAGE_DEFINITIONS` in `composables/useLanguageSelector.ts` (with
    its label under `languages` in each `app.json`). Bundles load on demand; Arabic (`ar`) and Hebrew (`he`)
    switch the layout to right-to-left. English-only? Remove the `ru` folder and its entry.
- **Admin**: drop `<code>.json` into `src/i18n/locales/` and add one line to
    `src/i18n/locales.ts` (mark `rtl: true` for right-to-left). Bundles load on demand.
    English-only? Remove the `ru` entry and its JSON.

**Language detection.** The app's language setting starts on **Use system language**: it takes
the device's language (the OS language on iOS / Android, the browser's preference list on web and
desktop), matches the exact tag first and then the base language (`pt-BR` → `pt`), and falls back
to English when the app doesn't speak it. A language the user picks in Settings overrides it. The
admin starts in the language last chosen in the panel, otherwise the browser's language if the
panel has it, otherwise English.
