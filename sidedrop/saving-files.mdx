Incoming files are streamed into your browser's own storage as they arrive. When one is complete it shows
**Ready to save** — then it's your turn.

## Save one file

Tap **Save** on the item:

| Browser | What happens |
| --- | --- |
| **Chrome, Edge** (desktop) | A system **Save as** dialog — choose where the file goes. It's saved under its own name, without the folder it came from. |
| **Firefox, Safari, phones** | It downloads to your browser's usual Downloads location. |

## Save all

With **two or more** files ready, **Save all** appears:

| Browser | What happens |
| --- | --- |
| **Chrome, Edge** (desktop) | Pick a folder; Sidedrop recreates the sent folder structure inside it. Files with the same name are **overwritten**. |
| **Firefox, Safari, phones** | Everything downloads as one `sidedrop.zip`. The zip is built in memory, so for a very large batch, save files one by one instead. |

## Text

A text snippet arrives as **Received**, with a one-line preview and a **Copy** button. Text isn't included
in **Save all**.

## Browsers that buffer in memory

If your browser can't stream to its own storage, Sidedrop keeps incoming files in memory and warns: *This
browser buffers incoming files in memory, so very large files may not fit. Chrome or Edge on desktop have
no such limit.* For big transfers, receive on desktop Chrome or Edge.

## Clearing up

- **Clear finished** removes saved, received, canceled and failed items from the table.
- A received file is removed from the browser's storage once you **Save** it.

<Warning>
    Starting a **new room** or **joining another code** in the same tab discards files that are ready but
    not yet saved. Save first.
</Warning>

<Note>
    Files you received but never saved — and canceled or failed transfers — can stay in your browser's
    storage after you close the tab. To remove them, clear the site's data for sidedrop.burakov.net in your
    browser settings.
</Note>
