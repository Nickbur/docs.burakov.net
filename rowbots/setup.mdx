Setting up takes two kinds of work: **forms** for the mechanics (connections, keys, budget) and an **interview** for
judgment (your vision, taste and priorities). Autonomy stays off until both are done. You can stop at any point and
resume later — the dashboard shows how far you've got.

## 1. Sign in

Open [app.rowbots.dev](https://app.rowbots.dev) and sign in with your email and a one-time code. Your workspace is
created with you as its **Owner** — the account that holds the plan and pays for it.

## 2. Connect your git host

In **Connections → Repositories**:

| Host | How it connects |
| --- | --- |
| **GitHub**, **GitLab.com** | Install the Rowbots app on your account or organization and pick the repositories. It gets narrow, revocable permissions — enough to push branches and open pull requests. |
| **Self-hosted GitLab, Gitea, any other server** | A service-account token for pull requests, plus a deploy key for git over SSH. |

Rowbots never asks for a broad personal access token. Your **14-day Studio trial** starts when you connect your first
git account — see [Pricing](/rowbots/pricing).

## 3. Connect model providers

In **Connections → Models**, add at least one key — OpenRouter, Anthropic, OpenAI, Replicate, Claude through
Bedrock, Vertex AI or Foundry — or an OpenAI-compatible endpoint you host. Connect two different model families if
you can, so the judge's exam is written by a different family than the code. See
[Your own models](/rowbots/your-own-models).

## 4. Choose where code runs

Your code always runs on **your** compute. In **Connections → Compute**, either add your **E2B**, **Daytona** or
**Modal** API key, or enroll a **self-hosted runner**. See [Compute & sandboxes](/rowbots/compute).

## 5. Add projects

A **project** is one product, made of one or more repositories. In **Fleet**, add a project and pick its repositories.
When one repository holds several products, give each project the paths it owns; paths no project claims are treated
as your **shared platform**. See [Projects & your fleet](/rowbots/projects-and-fleet).

## 6. Take the onboarding interview

Rowbots studies each repository first — its code, dependencies, tests and docs — then interviews you, one question at
a time, each with a recommended answer you can accept or change:

- your **product vision**, invariants, taste and priorities — this becomes the **constitution**;
- how you commit and name branches;
- each repository's **verification recipe** — how to build, test and run it (see
    [Verification recipe](/rowbots/recipe));
- which **expert profiles** may work on what (for example "anything touching auth also gets a security review").

For a new product, the interview helps you shape the vision first. Nothing enters the constitution until you confirm
it.

## 7. Set budgets and preferences

| Setting | Where | Default |
| --- | --- | --- |
| **Monthly spending cap** | **Budget** | — (required) |
| **Compute cap** *(managed sandbox providers)* | **Budget** | off |
| **Attention budget** | **Settings** | 30 min a day |
| **Commit authorship** | **Settings** | `rowbots[bot]` |
| **Artifact language** — for the constitution, pull requests and commits | **Settings** | English |
| **Post-merge observation window** | **Settings** | 72 hours |
| **Notifications** | **Settings → Notifications** | in-app and email |

## 8. Autonomy switches on

Once the constitution is confirmed and the budget is set, Rowbots starts working. Its first pull request in each
repository adds a `.rowbots/` directory — the constitution's read-only copy and the recipe — for you to review and
merge like any other change.
