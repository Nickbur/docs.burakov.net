title: "Security & privacy"
description: "How code runs in isolation, where your code and keys live, how outside input is contained, and how your data is retained and deleted."
---

Rowbots writes and runs code in your repositories, so its security model starts from one rule: **code
under test is never trusted**, and neither is text from outside your team.

## Sandboxing

- **The engine runs outside the sandbox; the sandbox only executes commands.** Model keys and git
  credentials never enter it, so code inside the sandbox has nothing to steal. Branches are pushed and
  pull requests opened by the engine, from outside.
- **A fresh sandbox per run**, destroyed afterwards. Your working copy, builds and tests live only there.
- **Network access is denied by default.** The sandbox can reach package registries and your git host;
  any other host must be declared in your project's recipe and confirmed by you.
- **Test secrets** enter a sandbox only when the recipe declares them and you agree.
- **The judge uses its own fresh sandbox** on the exact commit under review.
- **Self-hosted runners** isolate sandboxes with gVisor; managed mode uses your own sandbox provider
  account.

## Where your code lives

**Code-bearing artifacts live where the code lives.**

| Mode | Code, code index, hidden exams, traces | Model keys and git credentials |
|---|---|---|
| **Self-hosted runner** | only on your machine | only in the runner's configuration |
| **Managed sandbox** | in Rowbots storage, encrypted with a key unique to your workspace; code passes through the engine in memory only | in an encrypted vault, decrypted only in memory for the job, never logged |

In both modes, only job status, verdict summaries, pull request links, cost and usage, decision logs and
escalations reach Rowbots' control plane.

## Outside input is quarantined

Error reports, store reviews and support messages can contain anything — including instructions aimed at
an AI. That text is read only by a triage step with **no tools, no code and no secrets**, which turns it
into a structured item. The agents that write code see only those structured fields, never the raw text.
Outside input can only start maintenance work (bugs, security, performance); feature requests from the
public become proposals for you.

## Tools from other services

Rowbots agents can use external tools through MCP servers you allow per project. Their results are
treated as data, not instructions. **Autonomous work may use read-only tools only**, unless your
constitution explicitly marks a tool as writing to a reversible development resource, such as a test
database. Local MCP servers run only on your compute, in a sandbox separate from your code.

## Your data

- **Never used for training.** Your code and data are never used to train models. Sharing anonymous,
  non-proprietary patterns across customers is opt-in.
- **You own the output.** All code in the pull requests is yours.
- **Model and sandbox providers you connect** with your own keys are your own processors, under your own
  agreements with them.
- **Export** all workspace data at any time.

| Data | Kept for |
|---|---|
| Working logs and traces | 90 days |
| Excerpts from outside channels | 180 days |
| Code index and hidden exams | while the project is connected; deleted within 30 days of disconnecting |
| Audit log | 1 year |
| Backups | 30 days |
| Everything, after you delete your account | deleted within 30 days |
