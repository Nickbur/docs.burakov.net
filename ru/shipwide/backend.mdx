Бэкенд-половина набора — Fastify + Drizzle + PostgreSQL + Redis. Single-app: одно развёртывание
обслуживает один продукт. Источник истины — код.

## Архитектура модулей

Три слоя на фичу — держите все полными:

```
src/modules/<feature>/
├── <feature>.service.ts   — чистая бизнес-логика, без HTTP. Все функции экспортированы.
├── <feature>.handlers.ts  — обработчики Fastify. ВСЕ экспортированы, даже если не смонтированы.
├── <feature>.routes.ts    — ТОНКАЯ дефолтная проводка. Делегирует хендлерам, не переписывает.
└── <feature>.schemas.ts   — Zod-схемы. Все экспортированы.
```

Поддерживающие слои: `src/config` (zod env + константы), `src/db` (клиент Drizzle, схема, миграции,
сид), `src/plugins` (cors, rate-limit, auth, swagger, обработчик ошибок), `src/shared` (ошибки,
крипто, uuidv7, правила username, email, сериализаторы), `src/jobs`.

<Note>
  Каждая экспортируемая сервис-функция, хендлер, схема и тип — **готовый строительный блок**.
  Экспортированный хендлер, который не монтирует ни один дефолтный маршрут, — **не** мёртвый код.
  Удаляйте что-то только если оно сломано, это настоящий дубликат или нарушение архитектуры.
</Note>

## Модель авторизации — только беспарольная

Одна модель: шестизначный email-код. **Вход и регистрация — один и тот же акт** — первый валидный
код для неизвестного адреса создаёт аккаунт. Ни пароля, ни разделения регистрация/вход, ни сброса,
ни отдельной верификации email.

- `POST /v1/auth/code` — шлёт код письмом. **204 на любой адрес** (не оракул перечисления). Жизнь
  10 мин, 5 попыток, одноразовый, хранится хешированным, сравнение за постоянное время.
- `POST /v1/auth/code/verify` — **вход** · **создание-и-вход** (username авто из email) ·
  **`deletion_pending`** (мягко удалён → `restoreToken`).
- Рядом доступны Google / Apple.
- Access 15 мин, refresh 30 дней, HS256, ротация при каждом обновлении; пара привязана к строке
  `sessions`; проверка живой сессии кэшируется в Redis с откатом на БД.

<Warning>
  Не возвращайте парольный поток — беспарольность это осознанное продуктовое решение.
</Warning>

**Тестовые / ревью-аккаунты:** `TEST_ACCOUNTS=email:6digits,…` — фиксированный код для ревью App
Store / Google Play и CI. Проверяется только против заранее засиженного аккаунта `is_test`, так что
фиксированный код никогда не создаёт аккаунт. Каждый вход по фикс-коду логируется на уровне `warn`.

## Что в коробке

| Область | Маршруты |
|---------|----------|
| Auth | `POST /v1/auth/code` · `/code/verify` · `/restore` · `/token/refresh` · `/sign-out` · `/google` · `/apple/*` |
| Account | `GET/PATCH /v1/account/me` · `/username/check` · `/username` · `/email` · `/email/confirm` · `DELETE /v1/account` |
| Sessions | `GET /v1/sessions` · `/current` · `DELETE /v1/sessions` · `/:id` · `PUT /:id` |
| Upload | `POST /v1/upload` + чанковая загрузка start/append/status/complete/abort · удаление/раздача файлов |
| Push | `POST /v1/push/test` (проверка доставки на устройства вошедшего пользователя) |
| Support | `POST /v1/support/tickets` · `GET /v1/support/tickets` · `/:id` · `/:id/reply` |
| Subscriptions | `POST /v1/subscriptions/webhook` · `GET /me` · `POST /sync` · `GET /premium-example` — off до настройки |
| Gamification | `GET /v1/gamification/stats` — очки начисляются только на сервере |
| Admin | методы входа · пользователи (роль, удаление/восстановление/purge, сессии, entitlements, геймификация) · сессии · тикеты · загрузки · push · аудит · ops |
| Health | `GET /v1/health` · `/version` · `/app-version` (политика версии клиента) |

Интерактивная справка на `/docs` (Swagger UI). Прочие механики: **username** (авто из email, живая
доступность, кулдаун смены 30 дней), **смена email** по коду, **удаление аккаунта**, ощущающееся
мгновенным (сессии убиты сразу) с физическим purge через `PURGE_AFTER_DAYS`.

## Политика версий и гейт обновления

Приложение публикует политику версии, которую клиент соблюдает — задаётся в **Admin → Settings**,
без деплоя:

- **Latest version** → мягкая точка «доступно обновление», когда установленная сборка старее. Намёк.
- **Min. supported version** → **жёсткий гейт**: сборка ниже блокируется. Обеспечивается двумя
  путями — приложение проверяет `/v1/app-version` при запуске и ежечасно, **и** каждый запрос шлёт
  `X-App-Version`, поэтому API отвечает **`426 Upgrade Required`** на устаревшую сборку. Эндпоинты
  восстановления (`/health`, `/version`, `/app-version`) никогда не гейтятся.

Оставьте поле пустым, чтобы отключить половину. Отдельно `API_DEPRECATION` / `API_SUNSET` добавляют
заголовки RFC 8594 `Deprecation` / `Sunset` в каждый ответ `/v1`, когда заданы.

## Скрипты

| Скрипт | Что делает |
|--------|-----------|
| `switch_to_dev` / `switch_to_prod` | копирует `env/env.dev\|prod` → `.env` |
| `dev` / `build` / `start` | tsx watch / компиляция / запуск скомпилированного |
| `db:generate` / `db:migrate` / `db:studio` | миграция из схемы / применение / Drizzle Studio |
| `seed` | тестовые/ревью-аккаунты |
| `purge` | физически удаляет аккаунты после окна мягкого удаления (ежедневный cron) |
| `gamification:reset` | обнуляет очки всех на новый период (cron) |
| `admin:password -- 'pw'` | печатает хеш `scrypt$…` для `ADMIN_PASSWORD` |
| `test` | Vitest |

## Заметки по эксплуатации

- Контейнер стартует **`migrate → seed → serve`**.
- Запускайте **purge** ежедневно по cron; в прод-образе используйте скомпилированный путь:
  `node dist/jobs/purge.js`.
- Почта: направьте `SMTP_*` на транзакционного провайдера (подойдёт Postmark). Настройте **SPF,
  DKIM, DMARC** — при беспарольной авторизации код в спаме означает, что никто не войдёт.
- CORS: `CORS_ORIGINS` = точные веб-origin(ы); нативные схемы и `ADMIN_URL` админки разрешены всегда.
