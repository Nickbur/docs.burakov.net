Панель оператора — Vue 3 SPA на своём origin, работающая против `shipwide_api`. Она читает данные
каждого аккаунта и каждую переписку поддержки, поэтому раздавайте её **отдельно** от приложения и
поставьте за сетевой барьер (Cloudflare Access, IP-allowlist). Single-app: без реестра продуктов и
мультиапп-механики — поверхность ровно такая, какая нужна оператору одного приложения (аккаунты,
сессии, тикеты, загрузки, push, аудит, ops).

## Дизайн и i18n

- **Дизайн-система — сайта Shipwide** — те же токены/кнопки/бейджи/`<dialog>`/шапка/подвал, плюс
  метка `Admin` рядом с брендом, чтобы её не спутали с публичным сайтом.
- **Мультиязычность (en + ru для старта).** Язык + тема переключаются из шапки и экрана входа, оба
  запоминаются.
- **Добавить язык** — положите `<code>.json` в `src/i18n/locales/` + одна строка в
  `src/i18n/locales.ts` (`rtl: true` для RTL). Бандлы грузятся по требованию.
- **RTL заложен** — флаг `rtl` управляет `dir`; CSS на flexbox + логическом потоке.

## Быстрый старт

```bash
npm install
npm run switch_to_dev        # env/env.dev → .env (указывает на localhost:3000)
npm run serve                # http://localhost:5174
```

Vite вшивает `VITE_*` на этапе сборки → переключайтесь на prod **до** сборки. API должен разрешать
этот origin: `ADMIN_URL` в env API добавляется в CORS, поэтому `ADMIN_URL` и порт здесь должны
совпадать.

## Вход

Экран входа предлагает только то, что сообщает `GET /v1/admin/auth/methods`:

1. **Root-креденшелы** — `ADMIN_LOGIN` + `ADMIN_PASSWORD` (env API). Независимо от почты — работают,
   когда всё остальное сломано.
2. **Email-код** — беспарольный маршрут для сотрудников `/v1/admin/auth/code`.

Если включён TOTP, ни один маршрут не выдаёт сессию сразу — оба возвращают 5-минутный челлендж; код
восстановления работает в том же поле.

## Архитектура

```
src/
├── config/          # всё продукто-специфичное, управляется VITE_*
├── i18n/            # настройка vue-i18n + локали en/ru
├── core/            # переиспользуемая половина — не знает ничего о продукте
│   ├── api/ auth/ storage/ ui/ composables/
├── modules/         # каждый вызов API, в одном файле
├── stores/          # auth + chrome (Pinia)
├── components/      # шапка, подвал, диалог, тосты, части таблиц
├── views/           # по одному на экран
└── styles/          # дизайн-система, портированная с сайта
```

<Note>
  **`core/` никогда не называет продукт** — поэтому ребрендинг делается правкой `.env`, а не кода.
  Всё, что было бы захардкоженной строкой, живёт в `src/config/`.
</Note>

### Легко ошибиться

- **Один инстанс axios, не фабрика.** Обновление single-flight — два одновременных 401 не тратят
  каждый по ротируемому токену.
- **Обновление до истечения**, а не только по 401 — сессии админа короткие.
- **Токены в шифрованном IndexedDB** (неэкспортируемый `CryptoKey` + канарейка). Держит креденшелы
  вне открытого текста; не защита от XSS.
- **Гейт роутера — не граница безопасности** — API авторизует каждый запрос и перечитывает роль.
- **TypeScript зафиксирован на 6.x, не 7.x** — TS 7 убирает JS-`tsc`, который патчит `vue-tsc` 3,
  поэтому `build` падает под TS 7.

## Окружение

| Переменная | Дефолт | Заметки |
|-----------|--------|---------|
| `VITE_API_URL` | `http://localhost:3000` | API, которым управляет панель |
| `VITE_CLIENT_ID` | `admin` | Неймспейс хранилища / метка сессии |
| `VITE_BRAND` | `Shipwide` | Шапка и подвал — задайте имя вашего продукта |
| `VITE_SITE_URL` | — | Ссылка из подвала; пусто скрывает ссылку |

## Деплой

```bash
docker build \
  --build-arg VITE_API_URL=https://api.example.com \
  --build-arg VITE_SITE_URL=https://example.com \
  --build-arg VITE_BRAND="Your product" -t shipwide-admin .
docker run -p 8080:80 shipwide-admin
```

nginx раздаёт SPA, откатывается на `index.html`, кэширует хешированные ассеты навсегда /
`index.html` — никогда, шлёт `noindex` + `DENY`. Вне образа: (1) укажите `ADMIN_URL` в env API на
этот origin, иначе CORS откажет; (2) поставьте сетевой барьер спереди — публичная доступность здесь
не нужна.
