Движок вовлечения, который вы подключаете к действиям своего продукта: пользователи зарабатывают
очки, приложение показывает экран статистики, а — если включить — переход порога за период выдаёт
бесплатный период подписки. Поставляется **живым, с двумя демо-действиями**, и он **конфигурируем**:
свои действия добавляются в одном месте, код движка трогать не нужно.

## Механика

- **Начисление** — зовите `awardPoints(userId, actionKey)` там, где происходит действие, достойное
  очков. Движок ведёт **итог** плюс **разбивку по действиям**.
- **Награда (опционально, по умолчанию выкл)** — первый раз, когда итог пользователя пересекает
  `GAMIFICATION_REWARD_THRESHOLD` за период, ему выдаётся бесплатный период подписки (локальный
  `promotional`-entitlement — без стора, без вызова RevenueCat). Пропускается для того, кто уже держит
  entitlement (это win-back, никогда не перетирает активную платную подписку).
- **Сброс** — cron-джоб обнуляет всех в начале каждого периода. Период `none` = копить пожизненно.

<Warning>
  Очки **начисляются только на сервере** из доверенных точек — клиенту нельзя доверять самому себя
  оценивать, поэтому эндпоинта «добавить очки» намеренно нет.
</Warning>

## Таблица правил — единственное место правки

`shipwide_api/src/config/constants.ts` → `GAMIFICATION_ACTIONS`:

```ts
export const GAMIFICATION_ACTIONS = {
  daily_login:       { points: 10, labelKey: 'gamification.actions.daily_login' },
  profile_completed: { points: 50, labelKey: 'gamification.actions.profile_completed' },
} as const satisfies Record<string, { points: number; labelKey: string }>;
```

Чтобы добавить своё действие:

<Steps>
  <Step title="Добавьте строку">
    например `invited_friend: { points: 25, labelKey: 'gamification.actions.invited_friend' }`.
  </Step>
  <Step title="Начислите">
    Зовите `awardPoints(userId, 'invited_friend')` из серверного кода, где это происходит (`awardOnce`
    для разовых вех, `awardDailyThrottled` для действий раз в день).
  </Step>
  <Step title="Подпишите">
    Добавьте лейбл в `i18n/locales/*/gamification.json` приложения под `actions`.
  </Step>
</Steps>

Экран статистики рисует новую строку автоматически — таблица строится из правил, присланных сервером,
а не захардкожена в приложении.

## Демо-действия (удалить или оставить)

| Действие | Очки | Где начисляется |
|---|---|---|
| `daily_login` | 10 | `auth.service` — раз в UTC-день, на реальных входах (refresh не считается) |
| `profile_completed` | 50 | `account.service` — единожды, когда у пользователя впервые есть и имя, и аватар |

Оба — **best-effort**: сбой геймификации никогда не ломает вход или обновление профиля.

## Активация — только env

Движок и экран статистики **всегда включены**. **Reward-цикл по умолчанию выключен** — он раздаёт
реальный премиум-доступ, поэтому его включают явно. `shipwide_api/.env`:

| Переменная | Дефолт | Значение |
|---|---|---|
| `GAMIFICATION_RESET_PERIOD` | `monthly` | `monthly` · `weekly` · `none` |
| `GAMIFICATION_REWARD_ENABLED` | `false` | Включить награду порог → бесплатный период |
| `GAMIFICATION_REWARD_THRESHOLD` | `1000` | Очков для получения награды |
| `GAMIFICATION_REWARD_DAYS` | `30` | Дней бесплатного доступа по награде |
| `GAMIFICATION_REWARD_ENTITLEMENT_ID` | *(пусто)* | Какой entitlement выдавать; пусто = `pro` |

Награда переиспользует ту же таблицу `entitlements`, что и подписки ([Биллинг](/ru/shipwide/billing)),
поэтому выданный бесплатный период везде читается как обычный активный entitlement. Работает **без
аккаунта RevenueCat** — грант локальный.

## Планирование сброса

Запускайте по cron в начале каждого периода — **no-op при `none`**, поэтому та же запись cron может
оставаться, пока вы выключаете сбросы:

```bash
# ежемесячно — прод-образ: node dist/jobs/gamification-reset.js
0 0 1 * *   npm --prefix /app run gamification:reset
```

## Серверная поверхность

`awardPoints` (атомарно итог + разбивка, дёргает reward-хук при пересечении порога), `awardOnce`,
`awardDailyThrottled`, `GET /v1/gamification/stats` и джоб сброса. Операторы могут смотреть счёт
пользователя и делать ручной `adjust` (`{ delta }`, аудируется, не дёргает reward-хук) на странице
пользователя в админке. На клиенте `views/pages/account/Stats.vue` рисует итог (счётчик-анимация),
прогресс-бар до порога (только когда награда включена) и таблицу разбивки.
