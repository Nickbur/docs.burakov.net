Shipwide — мультиплатформенный стартовый набор: общая основа из реальных продакшен-приложений,
упакованная как переиспользуемая. Это точка старта для вашего продукта, а не готовое приложение.

## Как части соединяются

- **`shipwide_api` — единственный бэкенд.** И **приложение**, и **админ-панель** общаются с ним по
  HTTP; между ними больше ничего нет.
- **Приложение** (`VITE_BACKEND_URL`) и **админка** (`VITE_API_URL`) — разные origin: админка
  читает данные всех, поэтому развёртывается и защищается отдельно.
- **Приложение резолвит origin API один раз** через `getAvailableServer()`
  (`src/helpers/systemUtils.ts`) — единственное место, где каждый запрос получает базовый URL. Оно
  читает `VITE_BACKEND_URL`, апгрейдит не-локальный origin до HTTPS и кэширует выбор на сессию.
  Задайте ещё `VITE_BACKEND_FALLBACK` — и оно проверит оба и переключится на резерв; оставьте пустым
  — используется один бэкенд напрямую без проб.
- **Сайт** — самостоятельный маркетинг; единственная опциональная связка — форма поддержки,
  постящая в API при заданном `PUBLIC_SUPPORT_ENDPOINT` (иначе работает в demo-режиме).
- Каждый клиент шлёт `client_id` (приложение по умолчанию `app`, админка `admin`), чтобы API мог
  помечать сессии. Это заявление, но не авторизация.

## Общий контракт обмена

Приложение, API и админка согласованы:

- Один префикс версии **`/v1/...`**; поля в **camelCase**; таймстемпы **ISO-8601 UTC**; id
  **UUIDv7**.
- Ошибки плоские: `{ "code": "snake_case_reason", "message": "for logs" }` — клиенты ветвятся по
  `code`; `message` никогда не показывается конечному пользователю.
- Авторизация — **Bearer** (`Authorization: Bearer <access>`) — без кук, без поверхности CSRF.

## Модель авторизации — одна везде

Беспарольная: шестизначный email-код, где **вход и регистрация — один и тот же акт**. Рядом
Google / Apple. Access-токены короткие (15 мин) и ротируются при обновлении (refresh 30 дней),
каждый привязан к строке `sessions`, поэтому отозванная сессия умирает мгновенно. Админ-панель
использует ту же модель, ограниченную сотрудниками, с опциональным TOTP. Подробно в
[Бэкенде](/ru/shipwide/backend).

## Строительные блоки, а не готовое приложение

- **Каждая экспортируемая часть — готовый строительный блок**: обработчик, composable, функция
  api-клиента, компонент. То, что *сейчас* не подключено, — не мёртвый код.
- **Заглушки экранов сделаны намеренно** — экраны аккаунта / сессий / настроек это стабы. Набор
  даёт «водопровод», вы строите поверх.
- **Удаляйте код только если** он реально сломан (ссылается на удалённые таблицы / env / пакеты),
  это настоящий дубликат или нарушение архитектуры — а не просто «его пока никто не вызывает».
