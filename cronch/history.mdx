A scheduler you can't inspect is a scheduler you can't trust. Cronch records **every run** and keeps it for as long as you choose.

## What's recorded for each run

- **When** it started, and **how long it took**.
- **Status** — **Success** (exit code 0), **Failed**, **TimedOut**, **Cancelled**, **Running**, or **Skipped** (it didn't run — see below). See [Statuses, triggers & messages](/cronch/statuses) for what each one means.
- **Exit code** — or **—** when the command never got to return one (it timed out, was cancelled, couldn't start, or was killed by a signal).
- **What triggered it** — `schedule`, `manual` (**Run now**), `catch-up` (making up for a [missed run](/cronch/catch-up)), or `queued` (a run that waited for the previous one).
- **Captured output** — everything the job wrote to **stdout** and **stderr**, up to **256 KB of each**. Longer output is cut off with `… [output truncated]`. When something goes wrong before or around your command — a missing shell, a missing working directory, a timeout — Cronch adds a line starting with `cronch:` to stderr explaining it.

## Reading a rule's history

Click **Logs** on a rule. Its runs are listed on the left, **newest first** — the start time and status, and under it the exit code, the trigger and, once a run has finished, how long it took (*took 3s*, *took 2m 05s*). Select one and its stdout and stderr appear on the right. The view updates live, and your selection stays put as new runs arrive. It shows the **latest 200 runs**; older ones are still kept until retention removes them.

To find a particular run, type in the **search box** above the list: it shows only the runs whose captured output — stdout or stderr — contains that text. Clear the box to see every run again.

When a command fails, this is where the reason usually is — the error the job printed is right there, long after 3 a.m. has passed.

In the main list, each rule also shows its **last** run time and status and its **next** scheduled time, so you can see the whole picture without opening anything.

## Failure notifications

When a run fails or times out, Cronch shows a system notification with the rule's name and the result, so you hear about it without opening the window. The details are in the rule's history as usual.

## Skipped runs

When Cronch decides **not** to run a rule, the history still says so — a row with status **Skipped**, the time the run was due (for a queued run, when it was dropped), no exit code, and the reason in its stderr:

- **The previous run was still going** (policy **Skip**) — for a scheduled run, or a **Run now**.
- **The queue was full** (policy **Queue**) — one run was already waiting, so a further one is skipped.
- **A queued run was dropped** — you switched the rule off or paused everything while it waited, or Cronch quit. Its trigger is `queued`.
- **A missed run, with Catch up if missed off** — Cronch wasn't running or the computer was asleep. A backlog of missed runs is one row, at the first missed time.
- **A run that came due while everything was paused**, with **Catch up if missed** off.

A skip isn't a run: the rule's **last** time doesn't change, and neither does its status — except that a **Once** rule whose one run was missed is marked **Expired**. So if a rule "didn't run", its history tells you why.

## Retention

History is kept for the number of days set in [Settings](/cronch/settings) — **Keep run history for _N_ days**. The default is **30 days**; you can choose up to 3,650, or **0** to keep everything. Older runs are removed when Cronch starts, once a day while it runs, and when you click **Save settings**. A run that is still going is never removed.

<Tip>
    If a job is noisy (lots of output, running often), a shorter retention window keeps the history tidy and the database small. For a rare, important job, keep it long — or forever.
</Tip>

## Cronch's own log

Separately from your jobs' output, Cronch keeps a log of what **it** did — the shells it found, every run it started and finished, runs it skipped, and any error of its own:

- **Windows** — `%APPDATA%\burakov\Cronch\data\cronch.log`
- **macOS** — `~/Library/Application Support/net.burakov.Cronch/cronch.log`

It rotates at about 1 MB; the previous file is kept as `cronch.log.1`.
