## Settings

Open **Settings** from the header.

| Setting | Default | Range | Applies |
| --- | --- | --- | --- |
| **Launch Cronch at login** *(recommended — jobs only fire while it runs)* | On | On / Off | When you click **Save settings** |
| **Keep run history for _N_ days** *(0 = forever)* | 30 | 0–3650 | When you click **Save settings** — old runs are removed right away |
| **Export rules…** | — | — | Immediately — see [Import, export & moving machines](/cronch/import-export) |
| **Import rules…** | — | — | Immediately |

The **Documentation** button opens these docs in your browser, and **Back** returns to the rule list. Click **Save settings** before leaving to keep changes to the first two options.

## Launch at login, explained

Cronch runs your jobs itself, so it has to be running for them to fire. On its **first run** it turns on launch at login and shows a one-time banner about it. The login item uses the operating system's own mechanism:

- **Windows** — a **Run** entry named `Cronch` in the registry (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`), which starts Cronch with `--minimized`.
- **macOS** — a LaunchAgent at `~/Library/LaunchAgents/Cronch.plist`.

The login item points at **where Cronch is right now**. Every time you click **Save settings** with launch at login on, Cronch registers its current location again — so after moving the app, open it from the new place and click **Save settings**.

When launch at login starts Cronch, it starts hidden in the tray. You can always see what's scheduled by opening the window from the tray.

## The tray menu

Cronch lives in the system tray (Windows) or menu bar (macOS):

- **Add rule…** — open the window on a new rule.
- **Run rule ▸** — a submenu with your rules; pick one to run it now, exactly like **Run now** in the window (same overlap policy; a rule that's switched off can't be run).
- **Open Cronch** — show the window (always on the rule list).
- **Pause all / Resume all** — stop every rule from firing on schedule, then resume. The icon turns grey while paused. See [Missed runs, sleep & pausing](/cronch/catch-up#pausing-everything).
- **Quit** — exit Cronch. Running jobs are stopped, and nothing runs until you open it again.

Clicking the icon opens the window too, and so does starting Cronch again while it's already running.

<Note>
    **Closing the window does not quit Cronch** — it hides to the tray and keeps running. Use **Quit** from the tray menu when you really want to stop it.
</Note>

## Command-line options

| Option | Effect |
| --- | --- |
| `--minimized` | Start hidden in the tray. Used by launch at login. Ignored on Cronch's very first run. |
| `RUST_LOG` environment variable | Changes how much Cronch writes to its own log (`info` by default, `debug` for more detail). |

Only one Cronch runs per user: starting it again brings the existing window forward instead of opening a second copy.
