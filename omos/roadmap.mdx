OMOS is built in stages, from the kernel outward. Everything under **Planned** is future work, and timelines aren't
promised.

## Built

- UEFI boot via Limine, with kernel address randomization, on x86_64 — and in QEMU `virt` on ARM64 and RISC-V.
- Memory management, per-process address spaces and shared memory.
- A preemptive, priority-based multicore scheduler with performance/efficiency-core detection.
- See [Kernel](/omos/kernel) for details.

## In progress

| Area | Works today | Still missing |
| --- | --- | --- |
| **System calls and IPC** | Channels, notifications, wait sets, timers, handle rights and transfer — see [IPC & system calls](/omos/ipc) | Starting programs; capability checks for hardware access |
| **Filesystem and drivers** | User-space drivers, the filesystem service, FAT32 on virtio — see [Drivers & storage](/omos/drivers-and-storage) | Filesystems on NVMe and SATA; per-directory capabilities; restarting a crashed driver |

## Planned

<Steps>
    <Step title="Storage">
        A native filesystem, **OmosFS**.
    </Step>
    <Step title="Graphics and a desktop">
        A graphical interface.
    </Step>
    <Step title="Networking">
        A network stack, and a compatibility layer for existing programs.
    </Step>
    <Step title="Many machines as one">
        Pooling the processors, memory and storage of several machines you own into one system.
    </Step>
    <Step title="Virtual machines">
        Running other operating systems on top of OMOS.
    </Step>
</Steps>

Also planned along the way: a shell and command-line tools, an installer, user accounts, system updates, a Secure
Boot chain, and closing the [current security limitations](/omos/security#current-limitations).

Follow progress on the [OMOS page](https://burakov.net/projects/omos).
